# fabricext_lakehouse_onelake_security (Resource)

!> **Warning:** **Experimental Provider**: The `fabricext` provider is published in a pre-`v1.0.0` experimental state to facilitate automated packaging and supply-chain verification. For core workspace and item management, use the official Microsoft [`microsoft/fabric`](https://registry.terraform.io/providers/microsoft/fabric/latest) provider.

~> **Note:** For end-to-end guidance and real-world multi-persona security configurations, see the [Access Control Playbook](../guides/access_control_playbook.md).

Verifies that OneLake Data Access Security is enabled on a Microsoft Fabric **Lakehouse** and optionally purges the auto-provisioned `DefaultReader` role to enforce zero-trust least-privilege access control.

~> **Note:** Microsoft Fabric currently does not support enabling OneLake Data Access Security via public REST API. Enablement must be performed once in the Fabric portal via **Lakehouse ribbon -> Manage OneLake security**. This resource validates enablement and manages the `DefaultReader` role lifecycle.

~> **Important:** When OneLake security is enabled, Fabric automatically creates a `DefaultReader` role granting read access across all tables to anyone with workspace `ReadAll` permissions. Leaving this role active undermines fine-grained RLS and CLS permissions. By default, `remove_default_reader_role = true` automatically removes this role.

## Example Usage
```terraform
# Verify OneLake security enablement and purge DefaultReader role for zero-trust least-privilege
resource "fabricext_lakehouse_onelake_security" "raw_bronze" {
  workspace_id   = "00000000-0000-0000-0000-000000000001"
  lakehouse_name = "raw_bronze_lh"

  # Purge the auto-created DefaultReader role so only explicitly assigned roles grant access
  remove_default_reader_role = true
}

# Preserve DefaultReader role if legacy ReadAll access across all tables is intentionally desired
resource "fabricext_lakehouse_onelake_security" "shared_silver" {
  workspace_id = "00000000-0000-0000-0000-000000000001"
  lakehouse_id = "22222222-2222-2222-2222-222222222222"

  remove_default_reader_role = false
}
```

## Enablement Workflow

Microsoft Fabric currently requires OneLake Data Access Security to be enabled through the web portal before data access roles can be created:

1. Open the Microsoft Fabric web portal and navigate to your Lakehouse.
2. In the Lakehouse ribbon, select **Manage OneLake security**.
3. Confirm enablement in the dialog.
4. Apply your Terraform configuration managing `fabricext_lakehouse_onelake_security` and any `fabricext_lakehouse_permission` roles.

~> **Note:** If `fabricext_lakehouse_onelake_security` is applied against a Lakehouse where OneLake security has not been enabled, the plan fails with an actionable diagnostic pointing to the portal workflow.

## Zero-Trust Role Management

When OneLake security is enabled, Fabric automatically generates a role named `DefaultReader` with wildcard path access (`*`) and `Read` action for all workspace `ReadAll` holders:

- **Permit-Wins Semantics**: OneLake evaluates access across all applicable roles. If `DefaultReader` remains active, any user with workspace `ReadAll` retains full table read permissions regardless of custom Row-Level Security (RLS) or Column-Level Security (CLS) constraints.
- **Automated Purging**: Setting `remove_default_reader_role = true` (the default) automatically purges `DefaultReader`, ensuring that only explicitly configured OneLake Data Access Roles grant data access.
- **Reversion Guard**: Once purged, `remove_default_reader_role` cannot be reverted from `true` to `false` because Fabric does not offer an API to restore `DefaultReader`. If open read access is required, define an explicit `fabricext_lakehouse_permission` role.
